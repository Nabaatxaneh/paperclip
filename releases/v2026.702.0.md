# v2026.702.0

> Released: 2026-07-02

## Highlights

- **Billing/spend-limit failures no longer loop or burn the cap** — When an agent run fails because a workspace hit its monthly spending / billing limit, Paperclip now classifies it as a distinct, non-retryable outcome (`billing_limit_exhausted`) instead of a generic adapter failure. Billing-blocked runs are no longer immediately re-heartbeated or auto-retried by recovery, and the owning issue's monitor is cleared so it stops re-waking into a futile loop. This closes the workspace spend-exhaust failover cascade where a spend-limited workspace kept re-dispatching doomed runs and amplified the cost. (ALAA-1613 R2)

## Improvements

- **Routine re-check wakes start from a fresh task session** — Timer-driven and routine re-check wakes (`issue_monitor_due`, `issue_assignment_recovery`, `issue_continuation_needed`) now reset the agent's task session instead of resuming the long-lived one. These paths re-read the issue thread from the API on each run and carry no meaningful continuation state, so reusing the prior session only accumulated 2–5.5M cached-input tokens re-sent per run at $0.7–1.76/run. Starting fresh caps routine-wake context at roughly system prompt + wake payload + fetched thread. Active-synthesis and genuine continuation wakes still resume full context. (ALAA-1613 R3)

## Detection details

- A shared `isBillingLimitErrorMessage` matcher recognizes workspace spending-limit, billing-limit/threshold, credit-exhaustion, and quota-exhaustion phrasings across the normal failed path, the heartbeat error path, and the setup-failure path, mapping each to the `billing_limit_exhausted` stop reason.

## Upgrade Guide

No database migrations. Server-only behavior change; no configuration required. Rollback target is the prior published stable (`v2026.626.0` / runtime `2026.626.0`).
